## Context

Diners want details that a menu does not easily cover, and an easy way to order, by voice or by text. Every restaurant
has its own menu and setup, so one assistant has to serve many restaurants.

## Approach

<Flow
  label="How a customer's question becomes an answer or an order"
  steps={['Chat or voice in the browser', 'Speech to text', 'Flask service', "Language model, answering from the restaurant's live menu", 'Reply as text or speech', "Order sent to the restaurant's ordering system"]}
/>

The assistant answered from the restaurant's current menu, tracked the conversation, and converted a confirmed order
into a structured order sent to the restaurant.

<More label="Prompts, voice, menu grounding and multi-restaurant setup">
- **Prompt design.** A persona, rules for the conversation, an order format with a worked example, and the
  restaurant's menu, assembled for each restaurant when a session started.
- **Voice.** Speech-to-text for questions and text-to-speech for answers, with short spoken summaries of long replies.
- **Menu grounding.** Each restaurant's live menu was supplied in the prompt for every session, and prompts were tuned
  to keep answers to that menu.
- **Many restaurants.** Settings for each restaurant were kept in MongoDB, and each restaurant reached the service with
  its own access token.
</More>

## How it grew

1. A single-restaurant demo with a fixed menu.
2. Live menus fetched from the restaurant platform.
3. A multi-restaurant service with per-restaurant settings and secure access.

<More label="What each version changed">
Each version kept what worked and removed a limit of the one before: first the fixed menu, then the single
restaurant. The last version separated configuration from code, so adding a restaurant meant adding data rather
than writing code.
</More>

## Contribution

- Designed and developed the assistant's backend, including the prompts that supplied each restaurant's menu and the
  rules for the conversation.
- Developed the speech input and output, and the ordering flow that sent structured orders to the restaurant.
- Developed the multi-restaurant configuration: per-restaurant settings and secure access.
- Evaluated language-model platforms for running the assistant, which informed the choice of platform.

<More label="Requirements and demos">
- Collaborated with the product team to turn user needs into functional requirements.
- Developed demos and incorporated feedback into each new version.
</More>

## Lessons learned

- **Configuration as data.** Separating configuration from code meant that adding a restaurant required adding data
  rather than writing code.
- **Remove one limit at a time.** Each version removed a limit of the one before, and demos after each version
  supplied feedback for the next.
