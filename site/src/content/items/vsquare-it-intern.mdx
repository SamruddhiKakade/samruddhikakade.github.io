## Problem

Hours of recorded talks, in audio, video and text, with no way to search inside them. A listener looking for one topic
had to browse whole recordings.

## Approach

<Flow
  label="From recordings to a searchable library"
  steps={['Video', 'Audio extracted (moviepy)', 'Speech to text (Azure Speech)', 'Transcripts stored (Azure Blob Storage)', 'Indexes for text, audio and video (Azure Cognitive Search)', 'Search site (Flask, Bootstrap)']}
/>

The user picks which media to search, types a query, and opens the best match directly.

<More>
The user flow, from my design document:

<Flow
  label="The user flow I designed"
  steps={['Home: search box and media choices', 'Results with descriptions', 'Content page opens the match', 'Back to results']}
/>

Text, audio and video each have their own search index, so a query can cover one kind of media or all of them.
</More>

## How I worked

I gathered the requirements with the project's stakeholder and wrote them up. Then I wrote the design document, drew
wireframes and tested several options before choosing a stack. At the end of the internship I presented the result.

<More>
Options I tried before settling on a stack:

<div class="table-wrap">

| Area | Options tried | Chosen |
| --- | --- | --- |
| Storage | Local files, Azure Cosmos DB, Azure Blob Storage | Blob Storage with local files |
| Services | Azure Media Services, Video Indexer, Speech-to-Text, Cognitive Search, a search engine of my own | Speech-to-Text with Cognitive Search |

The final presentation walked through how I learned the services, what I tested, and why I settled on this design.

I took the project through every stage: requirements, design, wireframes, code and the final presentation.
