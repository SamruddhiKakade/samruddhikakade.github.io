## Question

When a system runs on its own, with no person checking each step, how do you engineer it to be reliable?

## Argument

Automated systems that people depend on need to be right the first time. Using electronic toll collection as a case
study, the paper argues for clear requirements, repeated review during development, and stress testing before
release.

<More>
The paper moves from software development and automation in general, to the toll-collection case study, to future
possibilities for automated systems, and closes with what engineers should do differently for systems that run
unattended.
</More>
